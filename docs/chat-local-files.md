# Conversation archive files

This guide covers local conversation archives only. Model profiles and credential storage are documented separately in [Model profile storage](model-profile-storage.md).

The chat page continues to save live conversations to the application server. To keep a user-controlled copy, use **Export JSON** for a UTF-8 archive download or **Import and view** to open one in a read-only view. Import validates the file before changing the displayed archive; use **Return to current conversation** to get back to the server-backed live chat. Imported messages and tool traces are never sent as model context and are not verified evidence.

On a secure page in a browser exposing the File System Access API, **Connect file for auto-save** opens a file picker. Pick an existing JSON archive or create a new file. Existing non-empty files must be valid archives; they are read and retained before conversations are merged by stable local conversation ID. Completed and failed/cancelled turns are written serially after the stream ends. Start a new chat to create a distinct archive conversation; older conversations remain in the file. Disconnect stops subsequent automatic writes. A cancelled picker leaves the existing connection alone. Permission and disk errors appear in the status row; the live server conversation remains available.

The browser File System Access API is not supported everywhere and requires a secure context and user activation. In unsupported browsers the page reports that limitation and provides JSON export/import; it does not claim automatic disk saving. File handles are session-only and must be selected again after reload. The archive stores only user and assistant text plus whitelisted tool traces, timestamps, and local grouping IDs. It excludes model profiles, API keys, owner access keys, chat session credentials, server conversation IDs, hidden reasoning, and arbitrary profile objects. The schema is version 1, limited to 5 MB and 10,000 messages.

Archives are local records, not a source of verified market evidence. Message text is rendered as React text; imported content is never executed. Tool trace names and JSON values are validation-limited and are display-only.
