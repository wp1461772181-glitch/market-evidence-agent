# V2 行情覆盖与价格口径审计

审计日期：2026-09-24。范围：AAPL、MSFT、GOOGL、AMZN、NVDA 与基准 SPY；训练计划范围为 2021-01-01 至 2026-08-31。本文是只读盘点，不会抓取或写入新的行情、训练模型或创建 artifact。

## 结论

本机已有行情只能覆盖 2023-08-31 以后，不能满足锁定的 2021–2023 训练分区。现有数据可以帮助验证 V2 数据构造代码，但不能用于声称已经完成 V2 纯行情训练。

Yahoo 的受限实测请求覆盖了计划范围，并返回了 GOOGL、AMZN 与 NVDA 的拆股事件。当前数据库没有保存这些请求的公司行动元数据、请求级价格口径检查或 V2 价格输入清单；所有本机历史行也都是后来导入的 initial backfill。因此，在保存新的、可回放的 V2 价格快照前，下文的“可用根数”都只是候选估计，不是可训练的 V2 样本。

## 审计方法

1. 从 `market_price_revisions` 读取五只股票与 SPY 的日期集合；每条当前行均保留，未修改数据库。
2. 使用 XNYS 日历检查一个根是否同时具有基准日、后续 20 个交易日的股票与 SPY 收盘价；分区要求根日和目标日都在同一固定分区，避免标签跨界。
3. 分别计算旧六个行情特征所需的 21 个连续交易日，以及 V2 语料计划要求的 61 个连续交易日（60 个前置会话加根日）。
4. 对每只股票执行一次只读 Yahoo Chart 请求，范围为 2021-01-01 至 2026-08-31，显式请求 `div,splits,capitalGains`。只记录日期范围、元数据验证状态与拆股，不保存或展示原始 provider 响应。

`provider_quote_close_v1` 的含义是 provider 的 quote close 价格收益；不包含现金分红再投资，不能称为总回报。

## Provider 拆股验证

五次实际 provider 请求均返回可核验的 quote-close 元数据。每只返回 1,421 个交易日，范围均为 2021-01-04 至 2026-08-31；结果如下。

| 股票 | provider 行为已核验 | 拆股事件 |
|---|---|---|
| AAPL | 是 | 无 |
| MSFT | 是 | 无 |
| GOOGL | 是 | 2022-07-18，20:1 |
| AMZN | 是 | 2022-06-06，20:1 |
| NVDA | 是 | 2021-07-20，4:1；2024-06-10，10:1 |

按当前 V2 合同，根基准日到目标日横跨未支持拆股时必须阻断。现有本机范围不含 GOOGL 与 AMZN 的 2022 拆股，但含 NVDA 2024-06-10 的拆股：61+20 候选中有 20 个根跨越该日（根日 2024-05-10 至 2024-06-07，目标日 2024-06-10 至 2024-07-09），全部在校准分区。因此即使价格快照被补齐，严格按当前 `provider_quote_close_v1` 规则的候选上限为：训练 20、校准 1,140、测试 1,980，合计 **3,140**。

普通现金分红在这个价格收益定义中不阻断样本，但后续快照必须保留其事件警告；不能将任何结果称为含分红再投资的总回报。

## 具体缺口与下一步

1. **训练价格缺口：** 五只股票和 SPY 均缺少 2021-01-01 至 2023-08-30 的本机行情。固定训练分区需要先补齐这段范围及各根的前置窗口，且不得把下载完成说成历史实时观测。
2. **价格证明缺口：** 当前 `market_price_revisions` 没有每批 Yahoo 请求的 `PriceBasisMetadata`、拆股/分红列表、请求内容哈希或 V2 价格 manifest。P3 训练数据只能使用新建、不可变的价格快照清单，不能直接给旧 revision 行贴上“已核验”的标签。
3. **拆股缺口：** 2021–2022 补数后，GOOGL、AMZN 与 NVDA 的跨拆股根必须按合同剔除；不应把 Yahoo 的 `adjclose` 混进 quote close 以绕过该限制。
4. **时间语义缺口：** 所有现有本机行均为 backfill；正式数据清单要标为 `historical_research`，并记录真实获取/观测时间。真实前向评估必须等待未来系统观测样本。
5. **证据数据缺口：** 当前 `data/v2/dataset-manifest.json` 有两份来源快照，但 `price_snapshot_files` 为空，且提取版本仍标为待完成；它不足以训练官方或媒体联合模型。

下一步应先实现并用小型 fixture 验收 `training_data_v2`：固定根目标、21/61 会话完整性、跨分区 purge、价格 manifest/哈希和跨拆股阻断。随后用受限批次补齐必要的历史价格快照并保存清单，再决定是否开始 P3 训练。P3 的纯行情模型即使训练完成，`joint_probabilities` 仍必须为空，直到 P4 的证据渠道验证通过。

## 2026-09-25 补充：受限价格快照已取得

`scripts/build_v2_prices.py` 已实现默认只读计划与显式、按股票受限的下载。第一次真实下载揭示 2021-01-01 元旦不是 XNYS 交易日；修复日历边界及失败退出码后，分两批保存 AAPL 及其余五个标的，共六份本地历史研究快照。每份各 1,421 个交易日，2021-01-04 至 2026-08-31 的 XNYS 会话无缺口，Yahoo quote-close 行为检查通过；拆股、现金分红、真实获取时间与文件 SHA-256 均写入被 Git 忽略的 `data/v2/`。再次运行只读计划显示待补股票为 0，并复核了六份文件哈希。可公开核对的清单见 [V2 数据集清单摘要](v2-dataset-manifest-summary.json)。

这解决了“没有价格快照”的数据准备缺口，但尚未生成训练行、执行跨拆股/跨分区剔除或训练/校准模型。上述原始只读审计仍反映快照取得前的本机数据库状态；快照是今天回填的数据，不能算当年的真实系统观测。

## 2026-09-25 补充：固定目标根行已构造

`app/training_data_v2.py` 从六份本地快照重新验证文件哈希、时间与价格口径后，使用 61 个完整前置交易会话和未来固定 20 会话，构造了 **6,425** 条纯行情根行：训练 3,305、校准 1,140、封存测试 1,980。排除原因分别为历史不足 300、标签跨固定分区 300、目标区间跨拆股 80；未知公司行动也会按 `price_basis_unverified` 阻断。所有已生成根行的 `remaining_sessions=20`，`realized_return_from_anchor=0`。这一步仅构造数据，没有训练模型，也没有用封存测试标签调参。
