# Market Evidence Agent 对话系统：设计、问题与评测

> 面试用材料。所有数字都是实测值，出处在文末"数据来源"。

## 1. 一句话介绍

一个个人股票研究助理：用中文对话查财报数字、新闻和已保存资料，也能让 agent 代为保存网页、拉取 SEC 原文、生成 AI 分析或预测。回答里每个数字都带引用，可以点开核对来源；所有写操作都要用户在确认卡上点"同意"才会执行。

## 2. 一轮对话怎么走

```
用户消息
  → 指代消解：每一轮把用户的话改写成一句脱离上下文也能读懂的规范问题（谁、什么指标、哪个时间；"它""第二条""去年"在这一步变成明确对象和时间）
  → 意图分类：A 查已保存证据 / B 常识解释 / C 超出范围 / D 产品操作（含写操作）
  → 工具循环（38 个工具：15 个读、20 个写、3 个卡片类；模型选工具，服务端执行）
  → 收尾作答（只能用本轮取得的证据，每个事实带 [n]）
  → 依据核对（数字、引用、事件断言）→ 不通过的行交给模型修复，修不好才删
  → 流式输出（SSE），引用在服务端重新读库复核后才发给前端
```

- 后端：FastAPI + LangGraph，会话状态存 PostgreSQL checkpoint，可中断恢复。
- 写操作：服务端签发一次性确认令牌，模型拿不到写权限；只有卡片按钮能确认（打字"同意"不算），这样网页里的注入文字、误输入都不能替用户确认。
- 身份：所有者能写本地数据库；游客只能读，唯一的"写"是游客浏览器里自己的研究队列。

## 3. 关键设计取舍（可以展开讲的点）

1. **核对依据，而不是靠句式规则判断真假。** 金融回答最怕编数字，但简单的"数字必须在来源里逐字出现"会大量误杀：
   - 来源表头写 "In millions"，回答写"3,318.39 亿美元"——按表头单位换算后比较；
   - 回答四舍五入到 3 位有效数字——按回答自己的精度比较；
   - 档案号、文件名、`sec.gov/.../789019/...` 链接里的数字——只要证据里出现过这个标识就不算"数字断言"；
   - 表格按整张表的引用核对，不要求每行都写 [n]；没有金额的标题不要求引用。
   被拒的行先交给模型带着"哪个数字在哪个来源里"的提示去修，修不好才删，并告诉用户删了几处。
2. **财务数字直接读 XBRL 披露值。** 年报正文的利润表经常被截断或排版错乱，最初"微软营收"被答成"没有可核验资料"。改为读 SEC XBRL 结构化数据，按日期和财年末月份推导 FY/Q，引用卡显示"SEC XBRL 披露值"；披露值能回答时跳过知识库检索。
3. **写操作失败要说人话。** 确认后失败时说清"哪一项、为什么、下一步"，内部错误码只进审计日志；成功时用资料标题说明保存了什么，"已保存"和"资料库里已有"不会同时出现。
4. **限时作答。** 软上限 90 秒或 15 万 token 时停止取证，用已有证据作答；硬上限 150 秒；模型返回不完整时重试一次。
5. **可诊断。** 每轮审计记录各阶段输出、被删的行和原因、写操作结果；写操作异常带 traceback 记日志。之前写操作失败全部被吞成一个错误码，根因只能靠猜。
6. **写操作的参数由谁决定：模型只指明对象，可选项由服务端规则算出，用户勾选。** 修订预测时，模型只说"修订哪只股票的预测"，拿不到"用哪些材料"这个参数：
   - 服务端按一条规则算出候选材料：预测后 7 天内发布的新材料，或预测前 30 天内发布、预测之后才收录的材料。已经用过且没有变化的材料，以及内容重复的材料，都不算；
   - 用户在卡片上勾选，按钮带的仍是服务端签发的一次性令牌，只认卡片上列出的选项；
   - 没有候选时，直接说明规则，以及最近几份材料各自为什么不算；用户点名的材料不在范围内时，也说明原因；
   - 同一条规则在服务端只定义一次：agent 的卡片、网页修订表单（通过只读接口）都从它取候选清单，修订接口提交时再按它校验一遍。

7. **语义在指代消解这一步由模型解决一次，下游只认这一句。** 每一轮都由模型把用户的话改写成规范问题：写明公司（带代码）、要做的事或指标、明确的时间。"去年"按公司财年换算，比如 2026-10-21 问微软的"去年"，就是"2025 财年（2024-07-01 至 2025-06-30）"；"最近一期"这类要由数据决定的说法保持原样。分类、取证、证据门、回答都以这一句为准，代码不再用正则或词表去解释"去年"。校验只留最小一层：不编造 ID 和链接；公司须出现在原话、历史或这句改写里；不能凭空写出用户没说过的未来年份。第一句没有任何上下文时，改写里的追问不弹卡，交给能查库的工具循环判断。

## 4. 怎么测的

- **影子环境**：同一份代码 + 生产库副本（临时库）+ 真实模型，不碰线上数据。模型用 DeepSeek V4.1 Flash（阿里云 Token Plan 的 `deepseek-v4.1-flash-1017`；早期用 OpenRouter）。
- **读套件**：21 组 56 轮，覆盖中文指代、财年季度切换、新闻改条件、"随便给个数"诱导编造、派生计算、引用文本里的注入、投资建议边界、英文提问、新会话不继承旧会话等。
- **写套件**：13 组，覆盖研究队列、网页保存、上传材料、SEC 扫描/拉取/刷新、AI 分析、翻译、预测与修订、行情初始化、卡片取消/改选/重复确认/旧卡失效、批准后同一轮继续回答、一次两个写操作、打字"同意"、申报核验。
- **判定**：每轮读审计（路由、工具、写操作结果、被删的行）+ 对临时库做只读 SQL 核对（写进去了没有、有没有重复写）+ 回答里不得出现内部错误码、内部 ID、工具名。
- **并行跑测**：互不影响的用例并行，共用状态（同一个研究队列）的用例串行，读套件前 4 组从 398 秒降到 165 秒。
- **线上冒烟**：游客只读；所有者只做可撤回的写（加入研究队列再移出）。

## 5. 发现并修复的问题（真实案例）

| 现象（用户看到的） | 根因 | 修法 |
|---|---|---|
| 问微软年报营收，答"没有可核验资料" | 摘录起点的正则不认 "INCOME STATEMENTS"，截到了资产负债表 | 读 XBRL 披露值；摘录起点识别多种利润表标题 |
| 正确的数字被删、剩下空表格 | 核对不认表头单位、四舍五入、链接里的 CIK 数字、表格行不逐行引用 | 按依据核对（见 3.1）；删行后整理空表/空标题 |
| 回答里直接出现 `<｜DSML｜ calls>` 工具调用文本 | 收尾步骤不给工具时，DeepSeek 把工具调用写成正文 | 剥离工具调用文本；只剩工具调用时重问一次 |
| 确认保存后 4 次失败 3 次，提示还说"没有生成确认卡（write_service_failed）" | 只有日期的发布时间没有时区被拒；残片网页；修订预测的接口拒绝；所有异常被吞成一个码 | 日期按 UTC；每类失败映射具体原因和下一步；异常记日志 |
| "把 MSFT 加入研究队列，然后告诉我营收"——加完就不管营收了 | 队列写入不返回状态，被判"未完成"，没进入续答 | 只报成功也算完成；续答按财务问题先读披露值 |
| 问"研究队列里有什么"，整句被拦掉 | 系统自身状态不是可引用来源，时间里的数字被判无依据 | 系统状态问题用状态本身核对 |
| 重复点同一张卡、点旧卡，只回"请再发一次" | 卡片状态不匹配直接报错 | 分别说明"已执行过""已取消""已失效" |
| 数字类问题线上 36 秒、影子 6 秒 | 先跑知识库检索，上下文变成约 3 倍 | 披露值覆盖所问指标时跳过知识库检索 |
| 让 agent "修正这个快照"，它自己挑了三份 SEC 申报就提交了；确认卡只写"修正预测 · GOOGL"；确认后回执说"已完成"，其实只是排队 | 工具让模型直接填来源；候选规则只写在前端；回执没读到嵌套的任务状态 | 模型不再填来源，服务端算候选、用户勾选（见 3.6）；接口校验同一时间窗口；回执如实说明在排队，并告诉用户怎么查结果 |
| 问"有谷歌股价预测吗"，答"不含任何目标价或价格区间"，引用还显示"来源已失效" | 读取工具只给三个概率，不给基准价、±2% 门槛和截止日；引用复核把门控附加的字段也算进去比较 | 读取时带上预测目标和判定区间，修订后同时给出上一版；复核只比快照本身的值 |
| 问"去年微软的营收"，"去年"被定成自然年 2025；换成"上一财年""前年"等说法，行为就不一致 | 新对话第一句跳过指代消解；提示词要求"自足的问题保持原样"，改写在"新问题"时还会被丢弃；"去年"由正则换算成"今年 − 1"，并据此作废模型对财年的理解；回答模型被告知"改写仅供参考，以原话为准"，又自己猜一遍 | 每轮都输出规范问题，下游只认它（见 3.7）；删除相对时间的正则和词表 |

## 7. 局限与下一步

- 事件类断言（任命、辞职、收购）的核对仍是词表，中文转述英文新闻时会误拒。
- 线上新上传的材料要等索引完成才能被知识库检索到。
- 复合写请求（"保存这条并加入队列"）模型偶尔只提出其中一项。
- 关闭知识库检索时，检索兜底路径的引用仍会显示"来源已失效"（线上开着检索不受影响）。
- 模型偶尔把英文状态词（如 queued）写进回答，需要在回答层再过滤一次。
- 新闻类回答仍慢（线上 80–100 秒）："总结刚才那两条"会重新联网检索，而不是直接复用上一轮的结果。
- 游客提出写请求而目标又有歧义时，会先追问是哪份文件，再说明需要所有者；应先说明权限。给指代消解的历史会截断长回答（表格后几行看不到），也会引出不必要的追问。

## 8. 面试常见追问（自答要点）

- **为什么不让模型自由回答？** 金融数字错一位就是事故。模型负责理解和组织语言，数字和引用由服务端核对；核对的是"依据"（单位、精度、标识、引用范围），不是句式。
- **怎么防止 prompt injection 写库？** 写权限是服务端签发的一次性令牌，绑定操作参数的摘要；模型和网页文字都拿不到；只有卡片按钮能确认。
- **怎么评测一个 agent？** 影子环境 + 真实模型 + 固定用例；每轮按审计和数据库核对判定，不靠人看；用例按共享状态分组并行跑。
- **遇到"模型偶尔这样"的问题怎么办？** 先看审计里每个阶段的输入输出定位是哪一层，再决定是改提示、改校验还是改工具返回——本项目里多数"模型问题"最后是工具返回缺字段或校验规则太死。
