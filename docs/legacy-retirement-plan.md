# 旧版工作台整改与数据清理方案

日期：2026-09-27。用户要求主代理规划验收、Luna 实施；在现有系统内完成，不引入新框架或另建一套工作流。

## 目标

用户只面对一套 Agent 研究流程：材料收集与核验 → DeepSeek 分析 → 研究简报 → Jev 判断 → 同目标修订 → 到期评估。旧版离线实验不再占用主导航或提供创建入口。

## 页面改动

1. 总览：五股研究队列使用当前预测、材料和监控的真实状态，不再以旧 snapshot 数量代表当前预测数量。
2. 预测：保留当前版本、简报、概率和蜡烛图，移除旧版创建按钮及旧档案面板。
3. 证据：保留 SEC 扫描、正文读取、来源核验、手动上传和 1–5 星；不依赖旧版预测存在。
4. 材料库：保留已交付的 AI 分析、原始材料、分析历史及准确版本跳转。
5. 预测修订：使用当前根、版本和新材料；复用同一修订逻辑，不再建立旧版概率不变的关联。
6. 评估：使用当前模型分组和独立根样本；未到期清楚显示等待，不加载旧 Week 4 固定评测文件。

沿用深绿色侧栏、克制的卡片和中文操作文案。现有六个 hash 路由兼容；空库、无预测和切换股票都能正常操作。行情通过独立只读接口读取，不让旧 dashboard 成为整个应用的前置依赖。

## 数据清理边界

- 先只读盘点实际记录、引用关系和数量，再生成精确清理清单。
- 新版复用 `_v2` 表，不得按表名或单一 `research_only` 状态粗略删除。
- 默认保留 SEC 材料、上传材料、人工核验、已付费 AI 分析及其冻结来源、行情和监控记录/配置。
- 拟清理范围为旧实验预测、旧修订、旧研究运行，以及能够证明全链均为旧实现的预测根和相关任务/评估。与保留数据有关联的行必须保留或明确阻塞，不使用级联清空。
- 使用忽略目录中的本地备份和恢复校验。清理工具默认 dry-run，实际执行前必须核对清单和备份；不删除表，不清空整个数据库，不自动清理来源材料或本地模型文件。
- 将具体数量和保留范围交用户确认后，才执行开发库删除。页面整改和清理工具准备不等待该确认。

## 分工与验收

- Luna UI：前端入口和各页面统一，构建与针对性自测。
- Luna 数据：盘点、备份、默认只读的清理工具及安全边界测试；获确认后执行清理。
- Luna 接口：独立行情只读接口及隔离数据库测试。
- 主代理：审查差异，独立工程测试，浏览器验证六页、空状态、材料原文跳转和移动端；确认备份可恢复、清理数量吻合且保留数据不变，统一提交并推送。

不为了验收触发批量付费模型调用，不把无到期样本说成预测效果已验证。
