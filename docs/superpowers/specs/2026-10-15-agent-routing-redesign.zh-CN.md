## 0. 为什么改

本周实测暴露的问题，根因大多不在“LLM 不够聪明”，而在**代码里的关键词表和多余的中间阶段**：

1. “帮我上网搜一下最近美光的新闻”搜出 3–5 月的：搜索工具靠关键词表猜“要不要限定时间”，表里没有“最近”。
2. “我要最近的行情，也就是半个月之内的”被当成股价查询：意图识别不知道上一轮是新闻搜索。
3. 搜“列表里没有的股票”要先过“代码必须出现在原话里”的规划校验，用户看到的是“我没能可靠地处理这个请求”。
4. 一轮要 4–5 次串行模型调用，其中的“规划”阶段不在原始骨架里，是后加的，既慢又是一类失败的来源。

## 1. 当前情况（`490a176`）

## 2. 改之后的情况

### 2.1 总体结构（吴鹏的设计）

四类，由**意图识别**分流（解析指代与意图识别保持两个独立阶段）：

| 类 | 内容 | 流程 |
| --- | --- | --- |
| A 知识检索 | 用到知识库/已保存资料/联网证据的问题，含“先查库再网上搜再比较”，以及“比较后按条件入库”这类读后写 | **固定前置一步**：知识库检索 → 置信度闸，结果作为状态交给**主力 agent**；agent 以**读类工具为主**（提示词里优先、默认前置），**写类工具同样可用**（仍需服务端确认令牌），可继续联网搜索、比较、按用户的条件提出入库，再回答 |
| B 金融一般问答 | 与系统数据无关的金融/公司常识（概念、运营模式…） | 直接 LLM 回答，不调工具，不进主力 agent |
| C 无关话题 | 与产品无关 | 固定话术拒绝，0 次工具调用 |
| D 动作/复合 | 写操作为主、需要问用户补信息、多步复合请求 | 无固定前置；agent 自己规划；工具集 = 全部类别（读 / 可逆 / 写）+ 卡片工具，写类仍需服务端确认令牌 |

**A 与 D 是同一个 agent 循环、同一份工具目录。** 工具按类别打标签（读、可逆写、有成本写、卡片、客户端动作），**权限边界只由“级别 + 所有者/游客 + 服务端确认”决定，不由 A/D 决定**。A 与 D 的区别只有两点：A 前面先做一步固定检索 + 置信度闸，且提示词以读类工具为重点；D 不做固定前置，提示词以动作和补信息为重点（由执行者决定实现，验收只看行为）。

```
START → resolve_reference（无可消解内容则跳过 LLM）→ classify_intent
      ├─ C → 固定话术
      ├─ B → LLM 直接回答（输出端保险，见 C3）
      ├─ A → 知识库检索 → 置信度闸 → 主力 agent（读类为主，写类也可用[需服务端确认]）→ 回答（只读证据）
      └─ D → agent 循环（全部类别 + 卡片工具，无固定前置；写类需服务端确认）→ 回答
→ record_log → END
```

### 2.2 逐条变更

| 编号 | 变更 | 说明 |
| --- | --- | --- |
| C1 | 路由保持两阶段 | 解析指代产出“不依赖上下文的一句话”；意图识别只负责分流。**无可消解内容时跳过解析指代的模型调用**：该对话首条消息、无待确认卡片、无结果集目录 → `canonical = 原话`（仍走原校验函数，保持不变量） |
| C2 | 意图标签改为四类 | 取代现在的 9 个 purposes（`saved_data`/`source_qa`/…）。复合请求归 D。`previous_purposes` 机制保留（只补时间窗口/数量的跟进沿用上一个请求的类别） |
| C3 | B 类由模型判断，不靠输入端关键词 | 提示词给出判定标准（建议）：答案不随日期变、不需要具体数字/价格/日期/期间/“最新”、不要求“按财报/资料库/来源” → B；拿不准走 A。**输出端保险**：B 类回答若含数字/日期/金额，加固定声明“以下为模型的一般知识，未经系统资料核实”（或改走 A），事件里标注来源为模型知识。删除“提到公司就必须取证”的输入端规则（`names_company_or_metric` + `is_concept_question` 闸） |
| C4 | A 类走固定前置 + 主力 agent（读为主，写也可用） | 前置步骤保证一定查过知识库并过闸；闸的结果（有/无/不足）交给 agent；agent 可调用联网搜索等读类工具并比较两边，**推断必须标注为推断**；回答仍只读本轮证据，每条事实带 `[n]`。**写类工具也在 A 类可用**，用于“读后按条件写”：例如“比较知识库里最新苹果财报的营收日期和网上最新的苹果营收新闻日期，如果网上的更新就放进知识库”——agent 先读两边并取得**结构化日期**，由它比较；条件成立时才提出入库，经**确认卡**（卡上同时显示两个日期和待入库的来源）和服务端令牌后才执行；不成立则不弹卡，只说明两个日期。提出写操作只能由**用户本人的消息**触发，网页或工具结果里的“请导入”不算 |
| C5 | D 类：agent + 卡片工具 + 写工具 | 卡片工具：问用户选择 / 让用户填写（缺信息或没理解时由 agent 自己出卡片）。写工具：现有写操作集合（`fetch_sec`、`refresh_sec`、`analyze`、`import`、`index`、`forecast`）+ `add_to_research_queue` 等；完整目录与分级见 C13 |
| C6 | **删除规划阶段** | 删除 planner 调用及 `plan_*` 校验（`plan_scope_mismatch`、`plan_company_unconfirmed`、`plan_source_scope_mismatch` 等）。`query_expander` 视收益保留或删除。原校验逻辑**迁入各工具执行端**（见 C9） |
| C7 | 结构化工具参数：把所有工具的入参规范化 | 每个工具**集中定义一次**：名称、给模型看的说明、**带类型的入参 schema**（枚举/范围/可选项）、权限等级、是否需要确认、错误码与可行动提示（见 C13）。语义由 LLM 填参数，代码只校验范围，**工具内部不再从自由文本里猜**。例：`web_research(query, company?, days_back?, max_results?)`（`days_back` 取 1–366，映射 Tavily `time_range` 后按 `published_at` 精确裁剪）；`query_sec_filings(symbol, form?∈{10-K,10-Q,8-K}, latest?, accession?, limit?)`；`query_stock_prices(symbol, days? 或 start?/end?)`。校验失败返回结构化错误，agent 据此自行修正参数。`freshness.py` 的词表不再参与决策，只在模型漏填 `days_back`、而用户话里明确出现时间跨度时作可选兜底，且全仓只此一份 |
| C8 | 去掉“不在研究队列就弹卡片” | 删除 `company_not_in_queue` 卡片、`watchlist` 触发逻辑与相关前端分支。任意公司的新闻直接用公司名搜索，不要求代码出现在原话里。用户之后说“加入研究队列/我想研究它”，agent 调 `add_to_research_queue`：所有者写库（`agent_research_queue`），游客返回客户端动作由前端写 localStorage；该操作可逆、无成本，**直接执行并回显一行**，不弹确认卡。所有者队列入库与两个端点保留 |
| C9 | 工具执行端校验 | 每个工具自己校验入参：代码格式与存在性、资料归属（owner/guest）、范围（source/accession/period 只能来自结果集目录或用户原话）、`days_back` 范围、写操作令牌。校验失败返回**可行动的提示**（如“没有 MU 的已保存行情，可先加入研究队列并抓取 SEC 原文”），让 agent 能顺势向用户提议 |
| C10 | 词表收敛：只留“校验型”和“护栏型”，不留“决策型” | 详见 §2.5。删除：`_execute_tools` 的 4 家别名表、`_expanded_web_query` 别名、两份 `_OTHER_COMPANY`、旧 `_classify_intent` 关键词分流、`TOPIC_GROUPS` 中只为规划服务的部分。网页“是否在讲这家公司”的核对改为**对照用户原话/工具参数里的公司词**。公司表（`company_directory`）**降级为可选**：只留一份小表，用于默认研究队列的展示和“中文名 → 代码”的建议，**不再参与路由、过滤或校验**（工具端若用已保存数据验证代码，可整体删除）。指标同义词合并为一份。加防漂移测试和遗留词表审计（见 3.4） |
| C11 | agent 限额：按原因停止、不丢证据 | 详见 §2.6。预算拆成“成功调用 / 重试 / 全局硬上限”三个，再加沿用的 token 与时长上限；到限额时按原因给不同提示（任务太多请拆分 / 工具连续失败并说明哪个、几次、原因 / 在原地打转），并把已取得的证据作为“部分完成”回答，不整轮报错。模型把工具调用标记写进正文（如 `<｜｜DSML｜｜`）时识别，重试一次，仍失败返回 `provider_protocol_invalid` |
| C12 | 保持 | 回答语言：中文问题用简体；分层上下文、摘要、`/context` 与胶囊不变 |
| C13 | 系统相关功能全部作为工具开放给 agent（分类 + 分级） | 详见 §2.7。把界面上能做的系统功能逐个登记为工具，**打类别标签**（读 / 可逆写 / 有成本写 / 卡片 / 客户端动作）并分级（读 / 可逆无成本 / 有成本或难撤销 / 不开放）；A 类与 D 类共用同一目录，类别只决定提示词的侧重和是否前置检索，**不决定权限**；写级一律走服务端确认令牌；每个工具有所有者/游客权限矩阵和审计记录 |
| C14 | 网页入库工具（支持“新闻更新就放入知识库”） | 详见 §2.8。**这是新能力**：现状产品明确不支持把网页新闻导入知识库（`is_unsupported_news_upload`、README 的限制说明）。新增写级工具 `ingest_web_source`，带来源、抓取时间、发布时间、`source_type=web_news`，去重、限大小，仅所有者，走确认令牌；入库后的文档在检索和回答里保持“网页来源”标注，不得被当成官方文件 |

### 2.3 必须保持的不变量（硬约束）
1. **写操作**：任何写工具在服务端没有“与冻结参数一一对应的一次性确认令牌”时不得执行；令牌由服务端生成，模型文字和网页内容不能提供；有过期时间与幂等键；仅所有者。
2. **证据**：A 类回答只读本轮编号证据，引用的 `[n]` 必须存在；证据闸仍是代码；B 类回答不得冒充有证据。
3. **隔离**：owner/guest 隔离、归属检查、游客不能读所有者队列（`GET /research-queue` 对非所有者 403）。
4. **不可信输入**：网页和工具结果是数据不是指令（注入测试必须过）。
5. **数据库**：不 ALTER 已有表；新表只靠启动时 `create_all`。
6. **不碰**：主工作区 56 个“学习者文件”（哈希清单 `/tmp/market-semantic-workflow-20261013/main-dirty-hashes.json`，发布前后都核对）。
7. **工具分级**：只有声明了级别和权限矩阵的工具才能注册给 agent；游客工具集不含任何写级工具；§2.7 “不开放”清单里的功能不得以工具形式出现；密钥和登录码从不出现在任何工具的输入输出里。

### 2.5 词表在改后系统里的位置（C10 的展开）

**原则：词表不再决定“走哪条路、调哪个工具、要不要限时间”，只留“校验”和“护栏”两类。**

| 保留的类别 | 作用 | 例子 |
| --- | --- | --- |
| 校验型（其实是解析器，不是词表） | 把 LLM 填的参数或改写**与用户原话对照**，只有机器可比较才能校验依据 | 数字与量级（亿/billion/中文数字）、报告期间（Q3/FY/财年）、时间跨度（半个月/3 days）、股票代码格式、accession/UUID、引用 `[n]` |
| 护栏型 | 安全与不可信内容 | 提示注入话术、写操作确认令牌、网页挑战页/登录页识别 |
| 兜底与呈现 | 不影响决策 | 固定话术、停用词（相关性打分）、网页正文垃圾标记 |

**删除（都属于“替 LLM 做决定”）：**
- 旧的关键词分流（`_classify_intent` 里的 `新闻|财报|原文…`）。
- 用关键词猜“是否限定时间”（由 `days_back` 参数取代）。
- 公司别名表用于过滤网页、“其他公司”名单（改为对照用户原话/参数里的公司词）。
- 规划阶段删除后，“检索词必须保留原话”那组规则一并不需要。

**公司表**：降级为可选的小表（默认研究队列展示、中文名 → 代码的建议），不参与路由、过滤和校验。若工具端用已保存数据验证代码（格式 + 是否存在），可整体删除。

### 2.6 C11：agent 限额与停止原因

**预算（建议值，按评测集的 95 分位数调整，写成配置）：**

| 预算 | 建议 | 说明 |
| --- | --- | --- |
| 成功的不同调用 | 6–8 | 去重后的调用计数，重复的相同调用不算新调用 |
| 重试 | 每个调用 2 次 | 仅限可重试错误（超时、429、5xx）；参数错误不重试，直接把错误交回 agent 修正 |
| 全局硬上限 | 12 | 含成功、失败、重试 |
| token、时长 | 沿用 `_turn_limit`、`MAX_SECONDS` | 不变 |

**到限额时按原因给出不同提示：**

| 原因码 | 判定 | 给用户的话 |
| --- | --- | --- |
| `too_many_steps` | 调用大多成功，但还有未完成的目标 | “这次请求包含的事较多。已完成：…；未完成：…。请把剩下的拆成单独的一条再发。” |
| `tool_failures` | 同一工具/同一参数连续出错，重试用尽 | “‘XX’ 工具连续失败 N 次（原因：…），已停止重试。可以稍后再试，或换个说法。” |
| `no_progress` | 重复或近似的检索，没有新证据 | “几次检索都没有得到新的结果，已停止。” |
| `turn_deadline` / `turn_token_budget` | 时长或 token 到限 | 沿用现有文案 |

**实现要点：**
- 到限额时先做一次**不带工具的收尾调用**：让模型列出“已完成哪些、没完成哪些”，用于 `too_many_steps` 的提示。
- 已取得的证据照常用于回答，标注“部分完成”，**不整轮报错**。
- 每次停止都在审计里记录原因码和各预算的消耗。

### 2.7 C13：工具目录与分级

**要求：界面上能做的系统功能，都登记成工具开放给 agent。** 分级如下（具体名称与现有接口的对应由执行者在代码里核对，下表是类别与规则）：

| 级别 | 例子（候选，需对照现有接口） | 执行方式 | 游客 |
| --- | --- | --- | --- |
| 读 | 已保存行情、最新预测、SEC 文件列表与原文、材料与 AI 分析、FAQ、知识库检索、联网搜索、研究队列、任务与监控状态、到期评估、历史回放结果 | 直接执行，按所有者/游客限定范围 | 按游客范围可用 |
| 可逆且无成本 | 加入/移出研究队列、切换当前股票、打开某个页面 | 直接执行并回显一行；游客的本地操作返回“客户端动作”由前端执行 | 可用（仅本地） |
| 有成本或难撤销 | 抓取/刷新 SEC、AI 分析、导入已保存资料、**网页入库（C14，新）**、建索引、创建预测、初始化行情、扫描官方文件 | 服务端一次性确认令牌 + 确认卡，仅所有者，幂等 | 不可用 |
| 不开放 | 修改登录码、查看或修改模型密钥与配置、清库、删除历史对话 | 只留在界面里；agent 被问到时说明“请在界面中操作” | 不可用 |

**规则：**
1. **每个工具必须声明**：名称、说明、入参 schema、级别、所有者/游客权限矩阵、是否需要确认、错误码与可行动提示；未声明者不能注册。
2. **分类标签 + 分组呈现**：A、D 两类共用同一目录；A 类的提示词把读类工具排在前面、说明写类工具“仅当用户本人要求保存/导入/抓取（含条件式要求）时才使用”；D 类以动作与卡片工具为重点。工具数量多时，每个工具的说明要写清“何时用、何时不用”，避免模型选错。游客工具集按权限矩阵裁剪，不按 A/D 裁剪。
3. **客户端动作**：游客的“加入队列/切换股票/打开页面”由服务端返回一个客户端动作事件，前端执行；服务端不写库。
4. **审计**：所有写级调用记录（谁、什么参数、令牌、结果），沿用现有幂等台账。
5. **删除类默认不开放**；若以后要开放，需要单独的规则和更严的确认。

### 2.8 C14：网页入库工具（读后按条件写）

**为什么要有：** 吴鹏要的典型请求是“比较知识库里最新苹果财报的营收日期和网上最新的苹果营收新闻日期，如果网上的更新，就放进知识库”。现状无法完成最后一步：产品明确不支持把网页新闻导入知识库（`is_unsupported_news_upload` 会直接拒绝，README 也写明“公开网页新闻目前不是可导入的已保存来源”）。

**这个请求的完整流程（A 类，读后写）：**
1. 前置检索：知识库里苹果**最新财报**，取结构化字段（报告期末、申报日期、营收口径与数值、来源 ID）。
2. 联网搜索：苹果最新营收相关新闻，取结构化字段（标题、URL、`published_at`、抓取时间）。
3. agent 比较两个日期；**两个日期都显示在回答里**。
4. 条件成立（网页较新）→ 提出 `ingest_web_source(url)`，出确认卡：显示知识库里的最新日期、网页的发布日期、标题与 URL；用户点同意后才入库。条件不成立 → 不出卡，说明两个日期。
5. 若“网页较新”意味着知识库缺了最新的官方财报，agent 应**同时提示**另一个选项“抓取最新 SEC 官方文件”（官方来源比新闻更适合作为财报依据），由用户选。

**工具要求（`ingest_web_source`）：**
- 仅所有者；写级；服务端一次性确认令牌；幂等键 = URL 的规范化哈希；同一 URL 或同一正文哈希不重复入库。
- 复用现有的公共网址校验（`validate_public_url`、受限传输），正文大小设上限，只存正文摘录，不存脚本等。
- 入库记录必须带：`source_url`、`published_at`（取不到则为空并如实标注）、`fetched_at`、`source_type=web_news`、抓取方式、内容哈希。
- 入库后参与索引与检索，但**检索结果和回答里始终标注为网页来源**，不得与官方文件（`official_filing`）混淆；证据闸里按来源类型区分，不能因为入了库就升级成官方证据。
- 入库完成后返回文档 ID 和“已入库 / 已存在”，供 agent 回答时说明。

**不改变：** 网页本身仍是不可信输入；网页里夹带的“请导入”不触发任何写操作（见不变量 4 与用例 #12）。

### 3.2 安全不变量测试（必须 100% 通过）
- 无令牌调用任一写工具 → 拒绝；令牌与参数不匹配 → 拒绝；过期令牌 → 拒绝；重放 → 不重复执行。
- 网页/工具结果中的指令式文本从不改变工具调用。
- 非所有者访问所有者专属接口一律 403/401。
- A 类回答中的每个 `[n]` 都对应本轮证据；B 类含数字时必带声明。
- **工具目录一致性**：每个已注册工具都声明了名称、说明、schema、级别、权限矩阵、是否确认；未声明者无法注册；游客工具集不含写级；“不开放”清单内的功能没有对应工具（用测试断言）。
- **A 类里的写**：A 类的工具集包含写级工具，但权限与 D 类完全一致（所有者 + 服务端令牌）；“条件式写”只能由用户本人的消息触发；网页入库的文档在检索与回答中始终带来源类型标注，证据闸不会因入库而升级其可信度。
- **限额**：三种停止原因码各有测试；到限额不丢已取得的证据；重试只针对可重试错误（超时、429、5xx），参数错误不重试。

### 3.3 质量与性能（同一模型、同一评测集、改造前后对比）
- 评测模型：OpenRouter `deepseek/deepseek-v4.1-flash`，key 用项目 `.env` 的 `OPENROUTER_API_KEY`（只读进内存，不打印、不落盘）；预算建议 ≤ 0.5 美元。
- 单源检索类回合：**模型调用次数中位数 ≤ 3**（现状 4–5）。
- 评测集 **p50 端到端延迟较基线下降 ≥ 25%**（基线由执行者先测）。
- 评测集整体通过率 **≥ 90%**；3.2 中的安全用例 **100%**。
- 不得出现因删除规划阶段而新增的“我没能可靠地处理这个请求”类失败（统计 `plan_*` 失败数：应为 0，且该原因码已不存在）。
