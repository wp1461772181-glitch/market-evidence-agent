# Market Evidence Agent 功能需求

> 本文定义目标行为与验收标准，不表示相关能力已经实现。需求聚焦确定性路由、可追溯证据和可恢复的任务执行；不规定具体代码结构或部署方案。

## 1. 目标与范围

系统应根据用户要完成的事情选择明确工作流，并能读取已保存资料、检索语义证据、研究公开信息、执行获授权的系统任务及进行一般对话。金融事实和分析结论必须能说明依据、时间范围与缺失部分。不得把订单、物流、退款等客服场景作为本项目需求。

固定技术栈为 LangGraph、State 与 checkpointer，用于正式图编排和会话状态持久化。现有读取和写入路线不要求新增云服务或数据库。本文定义目标行为，不表示相关能力已经实现。

## 2. 固定路由与意图

业务意图共七类，另有 `other`，共八个标签。意图表示用户目的；别名、实体和参数是独立槽位。一个复合请求可拆成多个叶子子任务，分别选择工作流。路由由下列有序规则确定：

1. 若存在待补槽位，先用本轮回复续办；仅当本轮明确提出新请求时才开启新请求。
2. 先把复合目标拆成可独立完成的叶子任务，再逐个路由。
3. 明确要求创建任务、抓取尚未保存的资料、刷新原文、生成新分析或写入索引，路由到 `system_task`。“获取已有摘要”“读取 SEC 原文”“看看分析结果”按只读请求继续判断，不因出现“获取”“分析”等单个词就触发写操作。无法判断是读取已有分析还是生成新分析时，只澄清这一点。
4. 请求整份已保存资料的概括、精确记录或该来源的已有 AI 摘要，路由到 `direct_saved_read`。原始来源事实优先读原文；AI 摘要读取已保存分析，并标明其为派生结果。
5. 请求资料中的特定主题、证据段落或 AI 分析中的主题性结论，路由到 `evidence_retrieval`；即使给出了 accession，也先将它用于限定检索范围，不因来源精确就把主题问答误判为整份摘要读取。
6. 明确要求搜索公开网页 / 新闻，路由到 `public_web_research`。
7. 其他可回答的一般问题路由到 `general_response`；目的或关键槽位无法判断时进入澄清状态。无法恢复或执行时进入错误终态。

五个工作流出口分别为 `direct_saved_read`、`evidence_retrieval`、`public_web_research`、`system_task`、`general_response`。澄清是可恢复的等待状态，错误是执行终态；两者不计为额外业务路线。工作流内 Agent 可在许可边界内选择工具，并可将额外来源步骤提交调度器校验；Agent 不得自行覆盖确定性路由或权限规则。

| 意图 | 典型请求 | 默认路由与约束 |
|---|---|---|
| `saved_data` 已保存数据读取 | “总结 AAPL 最新财报” | 精确读取已保存原文或结构化记录，先解析公司、表单、期间或 accession。索引缺失不得掩盖可读原文。 |
| `source_qa` 资料内容问答 | “这份 10-K 的风险因素是什么？” | 原始问题可按来源 ID / accession 检索原文；主题问题可在绑定来源范围内检索。AI 分析可作为单独标注的次级结果，不能替代原文事实。 |
| `analysis_qa` 已有 AI 分析问答 | “读取 accession X 的 AI 摘要”“AI 如何评价 AAPL 的风险？” | 精确摘要请求走 `direct_saved_read`，按指定来源和分析版本读取。主题性 AI 问题走 `evidence_retrieval`，按来源和分析版本检索；清楚区分原文与 AI 派生结论。 |
| `comparison_research` 比较研究 | “比较 AAPL 和 AMD 最新财报及近期新闻” | 拆成逐公司、逐来源和逐主题子任务，分派到上述五个出口中的相应路线；它是多路线扇出与汇总，不是独立出口。披露缺项，不强制全部走 RAG。 |
| `web_research` 公开网络研究 | “苹果最近有哪些相关新闻？” | 使用当前联网工具获取公开资料；抓取后检查来源、日期与相关性。不得因中文文章没有字面出现 `AAPL` 就判无结果。 |
| `system_action` 获授权系统操作 | “分析 accession X”“创建预测任务”“将资料加入资料库” | 检查身份、权限、输入和幂等键，再调用对应系统动作。读取和写入分开处理；不得把读取查询隐式变成生成或写入。所需 SEC 获取、分析、索引、预测动作应通过明确适配器提供；不得假称当前已经存在这些工具。 |
| `general` 一般对话 | 问候、能力说明或非业务的一般问题 | 问候可固定回复；能力说明依据实际可用能力注册表。实质性一般问题可在无业务工具的有限对话流程中回答，不要求所有闲聊都消耗模型调用，也不要求一律返回同一固定话术。 |
| `other` / 澄清 | 目的或关键范围无法判断 | 询问完成请求所需的最少信息，保留待续请求；不得硬塞进业务类别或猜测关键槽位。 |

意图分类只判断“要做什么”。分类器 JSON 严格为 `{"intent":"...","confidence":0.0}`，其中 intent 是上述八个标签之一，confidence 为 0 到 1 的分类器自评分。解析时允许去除包裹整个 JSON 的单个 Markdown 代码围栏，再校验 JSON、字段集合、类型、枚举和数值范围；不接受额外字段。别名、实体、来源、表单、期间和任务参数作为独立槽位提取并校验，不放入分类 JSON。分类响应格式错误或 schema 不符时，只做一次格式修复重试；仍失败则报告识别服务错误，只有输入本身存在真实歧义或缺槽位时才向用户澄清。confidence 不代表事实可信度或证据质量，不设会拒绝清晰、已验证精确请求的固定 0.7 门槛。只有真实歧义或缺失关键槽位时才最小化澄清；不能用任意阈值声称保证意图质量。提示应枚举八类并含边界示例。

## 3. 问题解析、指代与澄清续办

- 若问题清楚完整，原文问题保持不变。确有指代或口语歧义时，结合对话历史形成规范查询，同时保留用户原始问题，便于追溯。
- 将规范问题与经验证的实体分开保存。实体别名应经过明确映射，例如“苹果”可映射为 Apple Inc. / AAPL；`APPL` 是可能的拼写错误，但不得静默改成 AAPL，应提示确认。合法代码不得因模型猜测而被替换。
- 缺少会影响目标来源或操作的槽位时，在执行前要求用户选择或填写。选择项应使用易懂标签，并在可能时包含公司、表单、申报日期、期间及 accession。不得编造资料 ID 或 accession。
- 澄清期间持久保存待办请求、意图、已验证槽位和已选来源。用户回复“AAPL”或“就是 AAPL”时，应填入待办槽位并继续原请求，不应误判为一般对话。明确切换公司或来源时，清除该子任务的旧来源绑定；无关的临时提及不得自动改变当前研究焦点。
- 对比较请求逐个收齐公司槽位。若用户选择 AAPL 但另一家公司仍未知，应继续询问第二家公司；不得自行补出比较对象。只有双方都明确后才执行比较。
- 口语查询规范化应同时保留用户问题和规范查询。向 Tavily 等联网检索器生成中英文公司名、代码、主题词等变体时，不得限制为单一域名，也不得把扩写查询当成新的用户意图。

## 4. 金融资料选择与证据规则

### 4.1 资料解析优先级

按以下顺序处理来源选择：用户显式指定的操作和来源 > 精确来源 / 版本选择规则 > 内容语义匹配。用户给出表单、年份、期间或 accession 时，应优先遵从并验证其是否存在。缺少关键条件且存在多个候选时，先澄清。

- “最新”按资料申报日或发布日期判断，并展示该日期；不能用分析生成时间替代资料新旧。“财报”优先匹配 10-Q / 10-K；只有用户问“最新 SEC 文件”或泛指申报文件时，才将 8-K 等纳入候选。
- “AI 摘要”精确读取应按已验证来源读取该来源分析，不要求先有向量检索命中。明确指定 accession 时不得跳到其他来源。来源分析有多个版本时，取该来源最新有效版本，不取全库最新创建的分析。用户询问原始事实时，AI 分析不能替代原文；可另列为明确标注的次级分析结果。
- 原始主题性金融问题默认走 `query_materials` 语义证据路线。精确关键数字在有已保存结构化记录时可直接读取，并给出记录来源、期间、单位和版本；不得依赖虚构的 SQL 工具或无依据数字。
- 资料状态至少区分：原文存在但索引待处理、无分析、分析过期、无来源、服务暂不可用。索引不可用而原文可读时，直接来源读取仍可回答；需要生成或重建分析时，只有明确授权的系统任务才能执行，不得暗中副作用。

### 4.2 证据门控

证据门控依据“问题与实际证据来源”工作，而不是只按意图名称决定。精确读取至少验证来源 ID、内容、版本和出处；语义检索、联网内容和其后的工具观察都要在事实输出前核验支持关系。系统任务使用其自身的权限、参数和结果检查，不需要全局 RAG 闸门。

联网流程应先取回候选，再检查来源、发布日期、内容相关性及其对具体主张的支持。弱证据、冲突证据或日期不匹配时，缩小结论范围并说明限制。模型相关性判断可辅助筛选，但模型自评分不能保证事实正确。派生的 AI 结论须标明是分析结果，不能伪装成 SEC 原文。

证据不足时，最多进行一次有界的替代查询或直接来源查找；之后准确说明“资料未披露”“没有已保存资料”“索引处理中”或“服务不可用”等状态。若部分来源已验证、部分缺失，可报告有证据的部分并列出缺项；不得声称比较已完整。检索分数或覆盖度可作辅助信号，不能单独证明金融事实。

门控必须发生在事实内容发给用户之前，流式输出也不得先发送未经核验的事实再事后判定。可以先发送不含事实结论的进度信息。一般对话与系统操作不受全局 RAG 门控阻塞。

## 5. 查询扩写与检索边界

只有当金融主题查询确有歧义、涉及复合主题或重要证据覆盖时，才做检索侧扩写；简单精确读取不扩写。每次最多生成 3 条不同查询，结果按来源 ID、chunk ID 和版本去重。扩写只用于当前检索，不复制或扩增入库资料。扩写输出使用有 schema 校验的 JSON，例如 `{"queries":[...]}`；格式无效时做一次受限格式修复，仍无效则用原查询继续或说明无法完成检索。

“无检索命中”不得直接等价于“没有资料”。必须结合来源清单和索引状态核对。对同一公司、报告和主题应避免重复引用相同资料版本。

## 6. 模型协议、工具循环与失败处理

主 Agent 可采用 ReAct 风格的有界循环：简单请求一次工具调用即可收敛，复合请求按子任务逐步执行，缺槽位时返回澄清状态。默认上限为 5 次工具调用、6 次模型决策、120 秒和 32k tokens；各值可配置。重复相同参数调用应被识别并阻止，超时或预算耗尽时返回已核验的部分结果及可理解原因。

工具执行阶段和最终答复阶段必须区分。恢复并保留原前端工具调用轨迹，使用户能看到工具调用及结果。引用应可点击查看原文，也可复制答案。每个目标模型提供方须按其官方协议验证可用工具、`tool_choice` 字段、历史消息与工具调用 ID 配对、reasoning 字段要求及响应格式；不得假定某种 400 错误有单一根因。模型返回 400 时，应明确区分客户端参数 / 协议不兼容与无效密钥、限流等其他情形；保留安全的 provider 状态、request ID 和原因摘要，并对密钥及私有请求头脱敏。对未变化的请求不得自动重试 400。协议细节尚未确认时，应说明目标兼容要求及当前无法确认的根因，不宣称已定位根因。模型若在最终答复阶段返回工具协议内容，应按协议送回有界循环，或报告明确的协议不兼容错误；不得把协议标记原样展示给用户、静默忽略或假装任务已完成。

错误消息应标明发生阶段、用户可采取的动作及是否可重试。不得用通用英文占位问题代替中文澄清。保留有用的已完成子任务和结果，避免重试导致重复写入。

## 7. 系统任务、身份与会话状态

会话状态至少保存待办意图、槽位、所选来源、子任务状态、步骤、请求 ID、结果 ID、必要对话上下文和错误状态；不得在状态中保存密钥或凭证。每个子任务状态至少包括：`requested`、`planned`、`running`、`succeeded`、`partially_succeeded`、`failed`、`waiting_for_input`、`cancelled`。未执行或失败的任务不得标记为成功。

使用现有登录身份区分资料所有者与访客。已认证所有者的明确授权请求不需无故重复确认；破坏性操作仍须确认。访客不得获得写入权限。不得恢复旧操作密码或自行扩大当前权限。任务提交须支持幂等键；异步任务返回真实任务状态和结果，不得在任务未结束时伪称完成。取消、超时和部分完成均应可见。

## 8. 对话界面

- 每次回答前显示本轮实际调用的工具名称、执行状态和简短结果说明，不展示原始工具协议或 JSON 代码。
- 缺失股票、来源、表单或期间时，在聊天流中显示可点选选项及必要的手动输入；点击后回填待办请求并续办。
- 答案应显示实际使用的来源、申报 / 发布日期及可用的 accession；引用可打开或复制。表格和引用复用现有交互能力，不要求全面重做界面。
- 操作前显示任务状态或进度；失败时说明失败阶段、下一步和重试条件。部分结果应保留，重试不得重复已经成功的写操作。

## 9. 验收场景

以下为目标行为测试。相同场景应使用确定的资料夹具；索引状态等前置条件必须在夹具中真实成立。模型 / 工具模拟可测路由逻辑，但模型兼容性还须用目标提供方、模型和运行配置验证，不以模拟器通过代替真实兼容证据，也不要求公开密钥。

| 场景 | 前置条件与输入 | 验收结果 |
|---|---|---|
| 精确读取最新财报 | AAPL 有多个 10-Q / 10-K 及其他申报；询问“总结 AAPL 最新财报” | 按申报日期选最新 10-Q / 10-K，返回该资料的摘要、日期和来源；不因必须先命中 RAG 才读取。 |
| 指定 accession 且索引待处理 | accession `0000320193-26-000020` 的原文和 AI 分析存在，但相关 chunks 标记为 pending | 读取对应分析 / 原文并说明索引状态，不误报无资料、不跳到其他 accession。 |
| 语义财务指标 | 询问某期间的营收或现金流变化 | 引用支持材料，给出期间和单位；缺乏支持时不编造数值。 |
| 中文新闻检索 | 询问“苹果最近的新闻”，命中中文文章但正文未出现 `AAPL` | 通过公司别名和主题匹配评估文章；按实际来源与发布日期回答，不因缺少代码字符串而直接判无结果。 |
| 澄清后续办 | “比较这两家公司最新财报”后，用户选择 AAPL | 将 AAPL 回填为一家公司；第二家公司仍缺失时只询问第二家公司，不得猜测；双方明确后才比较。 |
| 显式切换来源 | 先选 AAPL，再明确改为 AMD | 后续 AMD 子任务不混入 AAPL 资料；先前独立子任务结果仍保留其来源标签。 |
| 股票代码疑似错字 | 输入 `APPL` 且无此有效目标代码 | 提示可能意为 AAPL 并请用户选择；确认前不静默替换。 |
| 无效分类 JSON | 分类器返回格式错误或 schema 不符 | 对分类执行一次有界格式修复；仍失败时报告识别服务错误；只有用户输入确实存在歧义或缺槽位才澄清，不把格式失败归咎于用户，不抛原始 JSON 或泛化英文问题。 |
| 精确摘要与主题分析分流 | 分别询问“读取 accession X 的 AI 摘要”及“AI 如何评价该公司的流动性风险” | 前者经 `direct_saved_read` 读取对应分析版本；后者经 `evidence_retrieval` 在绑定来源范围内检索分析。 |
| 比较多路线扇出 | 比较两家公司财报、历史分析和近期新闻 | 比较路线拆分后分别进入五个出口之一，汇总标注每项来源和缺项；比较本身不成为独立出口。 |
| 复合研究部分失败 | AAPL 资料可读，AMD 分析缺失 | 返回已核验的 AAPL 部分，明确 AMD 缺项；不得声称比较完整。 |
| 无披露内容 | 检索和来源核查后无支持资料 | 明确说未找到 / 未披露，并区分索引待处理、无来源和服务故障；不补造结论。 |
| 模型工具协议错误 | 目标提供方返回工具协议不兼容响应 | 显示可理解的失败阶段和重试条件，不向用户显示裸 `<...>` 协议内容，不标记成功。 |
| 身份与写权限 | 访客请求写入，已认证所有者明确提交同一操作 | 访客写入被拒；所有者请求按授权执行，不多余重复确认，破坏性动作仍确认。 |
| 幂等与任务完成 | 相同任务请求因网络重试重复提交 | 只创建一个有效写任务；只有实际完成后才报告成功，状态查询返回真实进度 / 结果。 |
| 取消与预算上限 | 任务取消或 Agent 达到调用 / 时间 / token 上限 | 状态准确标记取消或部分完成，保留已核验结果并解释停止原因。 |

## 10. 优先级

- **P0：** 固定路由表、槽位及澄清续办、来源 / 日期规则、索引状态区分、证据门控、工具协议错误处理、有界循环与准确任务状态。
- **P1：** 系统动作适配器、来源卡片与任务状态呈现、复合比较的独立子任务、受限查询扩写和结果去重。

## 技术栈约束

LangGraph、State 与 checkpointer 是用户指定的固定技术栈，用于正式图编排和会话状态持久化。现有读取和写入路线不要求新增云服务或数据库；框架实现须遵循本文路由、证据和状态行为。
