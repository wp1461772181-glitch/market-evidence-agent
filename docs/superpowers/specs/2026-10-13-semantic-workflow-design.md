# Semantic workflow and result continuation

## Intent and authorization
The user explicitly requested separate LLM calls using the currently selected Agent model, then authorized implementation. Prior discussion established reference resolution before intent recognition, conditional query expansion after routing, compound tasks with dependencies, and continued processing of previously retrieved results. This design implements that agreed scope without another approval prompt. It does not add business tools, media/news ingestion, new databases, model hosting, high concurrency, or an arbitrary autonomous planner.

## Current verified defect
Conversation inspection at release 8cfbd5d showed: Apple-revenue search returned two cited articles; “总结一下你刚刚找到的两条新闻的内容吧” became system_action/missing_action_type; “总结刚刚新闻的内容” became a fresh unscoped `news latest` search. Regex new-request detection, current-sentence-only classification, per-turn evidence reset and lack of result-set references caused the failure. Historical assistant prose survives, but authoritative numbered evidence was not restored.

## Architecture
Keep LangGraph, its PostgreSQL checkpointer, FastAPI SSE, the current provider/model configuration and existing tool registry. Resolve references, recognize intents, plan tasks, and expand retrieval queries in separate bounded LLM requests with distinct prompts and strict output schemas. All call the same selected provider/model/base URL/key, with credentials confined to request runtime. Each stage contributes to the shared time/token budget and emits a human-readable status. Rules validate formats, scopes, IDs, dependencies and permissions; they must not serve as the normal semantic new-request classifier.

1. **Reference resolution:** consume the current question, bounded recent same-owner conversation, prior pending slots, company/material focus and a catalog of trusted result sets. Return a canonical question, new/followup/slot-reply/clarify relation and references to actual existing result sets/items. Preserve entities, quantities, report periods and negation. Unknown or ambiguous references produce a targeted question with real choices; model/API failure produces an explicit stage error, not an operation-selection card. Never invent source IDs or use another conversation's objects.
2. **Intent recognition:** consume resolved task and bounded context; select one or more predefined purposes. Explicit saved AI analysis stays distinct from original material, summarizing existing results stays distinct from new web search, and conversational summarization never becomes a write operation. A repair attempt is bounded; malformed output is a stage error.
3. **Task planning:** a separate LLM call creates at most four validated subtasks with acyclic dependencies and explicit scopes. Only existing read/write operations and a summarize-existing-results operation are allowed. Search→summary is sequential; independent company queries have separate scopes/results (sequential execution is acceptable now). Existing write adapters retain owner authorization and durable idempotency; unsupported web-news upload remains an honest unsupported operation. Planning cannot create an implicit write, index, analysis or forecast.
4. **Conditional retrieval expansion:** a separate LLM call only for knowledge retrieval creates the original query plus at most two semantic variants. Preserve source/stock/date/number/negation filters in code. Expansion never runs before routing and does not turn an existing-result summary into a search. Source-scoped queries may expand within the same immutable source filter. Invalid expansion can retain the original query with an explicit degradation status; never silently fall back to regex expansion as the normal implementation.
5. **Execution and evidence:** execute validated task dependencies, reuse the existing tools and confidence/source checks, and assemble only passing evidence before final streaming. Ordinary public revenue-news requests require relevant articles, not unrelated structured financial-metric rows. Numeric questions still require actual numeric evidence. A failed upstream task cannot feed invented facts to a dependent summary; partial independent results are labeled.
6. **Persistent result sets:** after evidence passes checks, store bounded structured results in same-owner/conversation checkpointer state. Backend-generated stable IDs identify set, items, producing task/turn, company/topic scope, source URL/ID, excerpt and as-of/provenance. Retain at most six recent sets and 64 KB overall; context sent to resolution is a smaller metadata catalog. Preserve per-company groups and item order, so “刚刚两条/第二条/苹果那组” resolves reliably. Never cache rejected/failed results or credentials. Reused facts are reconstructed as current evidence with ordinals that map to the same sources; do not simply trust old assistant prose or strip citation checks. Existing verified server-side citation sidecars can seed legacy public-web result sets safely, with owner, provenance and URL checks. Invalid/missing legacy content clarifies or reads the exact original URL when available; no broad re-search or fabricated successful import.

## UI and compatibility
Keep the deployed chat layout and compact source cards. Show understanding/planning/expansion/reuse progress in plain language; keep source citations and tool badges. Ambiguous result references offer actual result-set/item choices and existing freeform input. Old operation cards, reload, model switches, stream cancellation, read-only archives and guest/owner isolation keep their guards. Optional injected stage callbacks support deterministic tests without invoking real providers; the normal production path uses the LLM stages.

## Acceptance
- Find two Apple revenue articles, then summarize them in a later turn: no operation card, no broad search, same two sources with valid citations, including after checkpoint reopen.
- Select “第二条” and choose a previous company group after a different company's query: exact existing IDs, no cross-company leakage.
- Search NVIDIA news then summarize in one request: validated search→summary dependency, no summary before evidence.
- Ask Apple price and NVIDIA news in one request: correct independent scopes, partial failure accurately reported.
- Original-only / saved-AI-only / compound original+analysis, explicit new goals, valid custom tickers and existing owner write adapters remain correct.
- Query variants use an independent model call and preserve identifiers/period/negation and exact-source filters.
- Unknown references, injected web instructions, invented model IDs, failed stages, stale choices and unsupported writes do not become authorized facts/actions.
- Real selected DeepSeek/deepseek-flash and Tavily/public SSE acceptance is independently run by the primary; mocked tests are labeled separately. Preserve all 56 learner edits. Root publishes only after review/tests.

## Independent plan-review invariants
- **Task-local scope:** freeze task_id, purpose, symbols, exact source/accession, date/period, result-set/item references and dependencies for each task. Build every tool call from its active task scope, not global focus/entities. A summary consumes only its declared dependency/referenced sets. Tests must assert a NVIDIA task never receives an Apple source/item ID, even when Apple was the previous focus.
- **Legacy trust:** a plain historical citation or assistant answer is insufficient to cache facts. Only same-owner/conversation/turn completed server records whose audit/tool evidence proves the returned excerpt passed the gate may seed a legacy web result set. Preserve safe URL, excerpt hash, publication/observation timestamps and producing trace/result identity. If historic records lack a sufficient proof, do not invent an authority marker: offer the actual sources or read only the selected safe original URL through existing guards. Failed/rejected traces cannot seed reusable evidence.
- **Budget contract:** each semantic node makes one normal model call; intent may make at most one schema-repair call. Every call accounts for prompt/catalog and response usage (uniform UTF-8 estimate if missing). Before calls enforce current 32,000-token / 120-second turn limits while preserving at least 5,000 tokens and 35 seconds for tool execution/final answer. The provider's existing per-call timeout remains bounded. If the required reserve is unavailable, return an explicit semantic_stage_budget_exhausted status rather than creating a clarification card or unscoped search. Expansion may use the original already-validated query only when sufficient execution/final reserve still remains, with an explicit degraded-stage status.
- **Reference fail-closed:** resolver returns an explicit relationship. Existing-result references must select catalog IDs and known item IDs; unknown/ambiguous/expired/cross-owner references terminate in targeted clarification/unavailable before planner/retrieval. They cannot be silently converted into new requests. A missing “刚刚的新闻” set never generates generic `news latest`; exact existing URLs may be read only when real known sources are available and selected.
