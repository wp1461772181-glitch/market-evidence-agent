## 0. 执行约定

用户的原始目标：**结合可搜集的信息预测股票趋势，给出支持和反对证据；后续信息出现时重新判断，保留旧预测；到期检验结果。**

用户要求实现简单：复用现有 FastAPI、PostgreSQL、React、scikit-learn、DeepSeek 和定时任务；不引入微服务、Kafka、Redis、向量数据库或多 Agent 框架。正方、反方、审查是固定工作流步骤，不必启动多个自主 Agent。

执行原则：

- 按 P0–P8 顺序推进；每阶段交付代码、必要测试、实际验收记录和 Git 提交。只勾选有证据通过的验收项。
- 当前已有的旧预测、原始材料、人工记录和价格修订不得删除或覆盖。新旧接口及模型语义必须隔离。
- 默认参数已在本文件确定。除真实阻塞、成本范围扩大或破坏性操作外，不重新进行一轮泛化需求访谈。
- 遇到模型数据不足，仍推进可独立完成的任务、监控和界面；同时记录模型阻塞，不能假装联合数值预测已经完成。
- 功能实现完成、模型离线达标、真实前向效果验证，是三种不同状态。报告时分别写明。
- 保持原用户的协作方式：主代理规划与独立验收，子代理负责有明确文件边界的实现。任务之间存在依赖时按序交接，禁止多人同时重写 `app/main.py`、`app/models.py` 或同一前端入口。
- 不读取 Vault 的密码文件，不输出任何密钥。仅让现有配置加载器使用被 Git 忽略的本机配置；密钥与本地原始材料不进 Git。
- 此阶段只运行本机系统。云部署、用户登录、交易下单、全网新闻采集不属于本方案。

## 2. 固定产品合同：先消除预测口径歧义

以下是本方案的具体默认设计。若用户后续明确改参数，更新 `target_spec_version` 并重训，不静默改变已有版本。

### 2.1 根预测

- 支持 AAPL、MSFT、GOOGL、AMZN、NVDA；SPY 只作辅助特征与比较基准。
- 默认未来 20 个 XNYS 交易日，基准为生成任务时最新已完成交易日的收盘价。
- 默认三类是股票自身价格收益：上涨 `R > 0.02`；横盘 `-0.02 <= R <= 0.02`；下跌 `R < -0.02`。
- `R = target_close / anchor_close - 1`。±2% 是明确的产品分类规则，不是证据权重或效果保证。
- 保存 `anchor_date`、`anchor_close`、`target_end_date`、`threshold`、`horizon_sessions=20`、日历版本、价格来源/版本/哈希、`price_basis`、`target_spec_version=absolute-close-v1`。
- 不调用旧 `mock-v1` 接口，不把旧超额收益概率重命名为绝对涨跌概率。
- 信息截止时间与行情截止时间分开。盘后新财报可以进入证据输入，而行情仍是最近完成日线；UI 必须同时显示两个截止时间。

### 2.2 固定目标修订

根预测代表一个固定问题。修订继承根的基准价、目标日、横盘阈值和收益口径。

例：9 月 1 日建立根预测，9 月 2 日发现财报。修订继续回答“9 月 1 日基准价到原目标日的涨跌”，不把目标日向后移动。

修订输入新增：

- `remaining_sessions`：当前行情交易日之后至原目标日的交易日数。
- `realized_return_from_anchor`：当前一致口径收盘价 / 根基准价 − 1。
- 当前可见行情特征及当前有效证据事件特征。

预测目标标签仍是根的最终收益类别。同一根各版的预测日不同，但目标完全一致。目标日已经收盘、或 `remaining_sessions <= 0` 时拒绝修订，转入复盘。

选择旧版进行手动修订时，可以建立分支：`root_id` 不变，`parent_version_id` 是用户所选版。根上加锁分配唯一版本号；版本号表示创建顺序，不代表它一定继承上一编号版本。

### 2.3 价格口径

现有 provider 请求了 `includeAdjustedClose=true`，但实际只读取 `indicators.quote` 的 OHLC，未存储 adjclose 或公司行动。不能据此宣称价格已经正确复权。

V2 初版采用 `provider_quote_close_v1`：训练、预测、标签、图表与回放均使用经过核验的同一种 provider quote 口径；预测价格收益，不加现金分红再投资。P0 必须用拆股样本和 provider 响应确认其行为，保存拆股/分红元数据和检查结果。

对已知跨拆股区间、无法确认的价格基准变化、端点口径不一致，初版阻断对应样本与预测/评估，显示 `price_basis_unverified` 或 `corporate_action_unsupported`。普通现金分红仍按价格收益定义处理，并标注除息事件；不得把价格收益叫总回报。禁止混用 quote close 与 adjclose；未来支持复权必须新建口径并重训。

## 3. 一次预测的统一执行流程

```text
创建任务
  -> 更新行情 + 扫描官方目录
  -> 冻结信息截止时间与本次输入集合
  -> 筛选增量材料 + 继承仍有效的证据背景
  -> 读取/提取结构化事实、去重并校验引文
  -> 正方研究 -> 反方研究 -> 本地证据检查
  -> 构造行情与证据特征 -> 运行匹配的联合模型
  -> 原子保存不可变预测版 + 输入清单 + 理由 + 模型清单
  -> 前端展示 / 监控后续信息 / 到期评估
```

所有入口调用同一业务函数：主动预测、手动修订、自动修订不各写一套处理流程。LLM 输入只来自本次允许的材料与行情摘要，不自行联网，不执行材料中的指令。

### 3.1 信息时间边界

1. `published_at/available_at`：来源公开时间；SEC 使用受理时间。
2. `observed_at`：系统真正收到材料或该更正版本的时间。
3. `decision_at`：冻结输入后确定的本次决策截止时间。模型运算结束时间另存 `completed_at`。

实时任务只允许公开时间和实际接收时间均不晚于 `decision_at` 的输入。之后收到的材料进入下一任务；计算慢不应偷偷改变输入集合。

历史研究允许 `historical_research` 模式使用有明确公开时间的历史回填，但必须记录实际回填/提取时间及假设；不能把今天发现的文件伪装成过去已观测。实际运行只用 `observed` 模式。

### 3.2 新旧证据的选择规则

- 新预测：优先处理上次成功研究之后新发现、内容变化或核验状态变化的材料；继承仍有效的背景事件。首次预测用最新可用年报、季报及近 90 天候选事件建立背景。
- 修订：继承父版有效事件，再加入所选/自动发现的新材料。旧材料失效、被更正、被撤回也属于变化。
- 新发现但早已公开的材料标成“补发现”，允许人工纳入当前研究，但不冒充“预测之后的新公告”触发自动修订。
- 新季报替代同指标的旧季度背景；未解决的重大经营风险保留。同一新闻转载不累计重复权重。
- 用显式事件键（股票、事件类别、所属期间/对象、来源关联）与内容指纹去重；不能仅依赖标题相似度自动合并。不能确定时保留待确认关联。
- 状态更新追加新事件版本；旧预测继续引用旧事件快照，不能被今天的核验结果改写。
- 没有新增材料时复用缓存与既有有效背景，正常更新行情预测；不重复调用 LLM 阅读相同正文。

### 3.3 文档读取范围与预算

- 第一版自动来源只做 SEC；公司 IR 逐站配置、媒体自动搜索列为后续扩展。
- 8-K 可能只有引导文字。需要识别同 accession 下的结果公告附件（例如 exhibit 99.1），仅沿已校验的官方目录抓取相关附件；仍执行域名/路径/重定向白名单与大小限制。
- 复用已有摘录能力，明确记录全文长度、选择的段落、分析覆盖范围和截断状态。只读摘录时 UI 不得写“完整财报已分析”。
- 默认每任务最多 10 份新材料；每份分析最多 24,000 字符的可定位段落，保留原始引文位置与来源哈希。超限记录 `coverage_incomplete`，列出未处理材料，分批继续；不能静默漏掉后显示“全部完成”。
- 试点阶段最多 30 份真实新文档、每次批量最多 40 个未命中缓存的模型请求；达到上限停止该批次并报告调用次数。扩大批量前提交明确数据量和费用估算，不无限抓取/调用。
- 模型名从现有配置读取，保存实际请求模型、提供方返回标识、prompt/schema 版本；不硬编码“最新模型”。

## 4. 证据真正进入数值预测

### 4.1 分工

- LLM：从给定材料抽取事实、组织正反证据和不确定性；不得直接输出最终三类概率，不得无来源补预期值。
- 本地校验：校验来源、时间、引文、单位、期间与重复关系；无法验证的数值不能进入模型。
- scikit-learn 模型：接受版本化特征，输出归一化三类概率；证据系数由训练学习，不手写“坏消息减 10%”。
- 解释：给出原始来源、事实变化及模型敏感性。敏感性只是模型行为，不声称事件造成了某个确定百分比的真实股价变化。

### 4.2 特征合同

V2 行情基线 = 现有六个行情特征 + `remaining_sessions` + `realized_return_from_anchor`。

第一批证据特征限定为可校验的少数事实，避免立即扩展数百项：

| 组 | 允许的输入 | 缺失处理 |
|---|---|---|
| 财务变化 | 同单位、同期间口径的 revenue/EPS 同比；没有两端原文依据时不计算 | 数值空 + missing flag |
| 指引变化 | 原文明确上调/下调/维持/未知；不能由“增长”推断“超预期” | unknown |
| 重大经营事件 | 召回、生产/服务中断、重大监管事件等预定义类别及状态 | none/unknown 区分 |
| 时间与状态 | 事件公开后时间、是否新事件、是否仍有效、是否更正/撤回 | 明确时间/状态，不默认有利 |
| 来源 | 官方/未证实媒体、独立来源数量、用户可信度 1–5 星与 missing flag | 官方星级不冒充用户评分 |

星级可以提供 `stars/5` 作为有名称的用户自评输入，但该数值不是经过校准的真值概率，也不能直接乘预测概率。来源可信度、事件影响程度和预测概率分别存储。

对同一事件只形成一个事件特征集合；多来源用于补充确认/冲突信息，不按报道条数无限叠加。第一版每个预定义事件类别聚合最新有效状态与冲突标志，保持少量固定特征；保存聚合前后的证据清单。

### 4.3 官方与媒体都要有明确完成状态

先完成官方事件模型，再将手动媒体接入相同事件合同。不能用只有官方财报的训练样本，声称已经校准了未经证实的媒体消息或用户星级权重。

媒体未具备验证数据时，上传、分析、研究结论与人工修订路径照常工作，但该来源数值影响必须返回 `unsupported_evidence_channel`，联合概率不伪造。**“官方能影响概率，媒体仍仅附说明”只能报部分完成，不能勾选整个 V2 完成。**

如果收集不到媒体验证样本，提交具体缺口和可选范围调整，由用户决定；禁止通过增加一个任意新闻权重绕过此门槛。

## 5. 数据、训练与效果验收

### 5.1 数据构建

1. P2 先清点现有本地材料、行情覆盖与精确来源时间；当前十份 Week 6 文档只用于流程验证，不当作充分训练集。
2. 官方历史数据候选范围：2021-01-01 至 2026-08-31，五只股票；按当前可用性获取 SEC 历史 submissions 分页及相关正文。先做 30 文档小批次检查抽取质量和费用，再分批扩充。
3. 每个根 anchor 生成初始行及候选修订行。初始 `remaining=20, realised=0`；修订日行情和证据截断到当时；同根各行共享固定最终类别与 `label_available_at`。
4. 训练包括无事件、正向事实、负向事实、冲突、材料不可用的不同情形；不能只保留成功调用或发生大涨大跌的事件。
5. 盘后公告样本可沿用当日完成日线、并纳入已公开公告；它与次日收盘样本分开，避免把公告后的行情反应泄漏到公告时点。
6. 同一事件/同根多行不能当成独立样本充数。训练时限制或加权同根修订行，报告原始事件数、独立根数和数据行数。
7. 历史媒体没有真实星级时保存缺失，不能在看到后续涨跌后补打星。官方证实/辟谣只在其公开之后影响当时可见状态。

新增 `scripts/build_v2_corpus.py`（P2实现）：从允许的来源列表分批构建语料清单，并复用现有行情采集补足对应历史区间与至少60个前置交易日；不是绕过单次预算的自动无限爬虫。命令至少支持 `--plan`（仅列缺口）、`--max-new-documents 30`、`--output-dir`、`--resume`。历史数据目录默认被Git忽略，Git中只放脱敏manifest摘要、哈希与获取方式。

`dataset-manifest.json` 最小合同：`schema_version`、`mode`、`symbols`、`source_snapshot_files`、`price_snapshot_files`、每文件sha256、公开/观测/抽取时间语义、价格与target规范、事件抽取版本、训练范围和三个分区。固定首轮分区为：训练2021–2023年，校准2024年，封存测试2025-01-01至2026-08-31。按下节规则剔除跨界标签/根/事件。若实际覆盖不足，报告哪些分区不足；改变划分必须先在manifest和进度文档记录理由，不能看完测试结果后挪动日期求通过。

### 5.2 防泄漏与模型清单

- 按时间划分 train/calibration/test；整个 root 留在同一分区，清除跨边界的目标重叠样本；同一相关事件及其衍生行不跨边界。继续按真实标签成熟时间 purge。
- 标准化、缺失填充、特征选择、参数选择只 fit 于训练区；校准只使用校准区；最终测试集封存，不反复调到通过。
- 历史回填显式标为研究数据。当前 LLM 处理旧文档可能带入历史知识：使用只提取事实的 schema、原文引文和输入白名单；不得把这种回测称为无历史知识污染的真实前向结果。
- 在历史研究中，今天运行的抽取器可作为受约束的研究变换，但实际抽取时间保持今天；实时回放不得借此读取后来出现的事实。历史研究训练候选模型是允许的，历史训练材料不要求当年就已被本项目抓取；需要严格区分研究假设与真实观测证据，避免系统永远因尚无数年前的运行日志而无法训练。
- artifact 必须包含 label/feature/prompt/schema 版本、数据哈希、划分时间、价格口径、支持来源渠道、模型可用时间、库版本和评估摘要。推理时全部兼容性检查通过才使用。
- `V2_MARKET_MODEL_DIR`、`V2_JOINT_MODEL_DIR` 指向明确的本机artifact版本（P3/P4新增配置）。新模型不自动覆盖当前目录；切换前校验清单、哈希及发布门槛，记录切换版本，旧预测仍绑定原artifact。历史模拟模型与实际上线可用模型的时间不能混淆。
- 只加载本项目可信、哈希匹配的模型文件；不从用户上传材料加载可执行模型。

### 5.3 模型发布门槛（方案默认验收规则，不是效果承诺）

比较三个同口径模型：类别先验、V2 纯行情 LR、V2 行情+证据 LR。沿用现有逻辑回归与独立校准流程，先不引入复杂模型。

默认数据就绪下限：官方模型至少 200 个去重事件组、覆盖至少 3 只股票与 3 年；校准集与封存测试集分别至少 50 个独立事件/根组，三类各至少 15 组。媒体渠道另有至少 50 个独立媒体事件的封存验证子集、三类各至少 15 组，并报告星级缺失情况。下限仅防止用极小样本宣称完成，不证明统计充分。

工程可运行但未达以下门槛：`research_only`，不能显示“已验证联合概率”。允许保存候选模型和敏感性结果，`joint_probabilities` 为空；纯行情基线放独立字段并清晰命名。

离线发布为 `experimental_joint` 的默认门槛：

- 所有时间、单位、引文和回放检查通过；数据覆盖达到上述下限。
- 对封存测试，联合模型 Brier 比同口径市场基线至少降低 2%（相对），log-loss 不高于市场基线；事件子集 Brier 也不高于基线；无事件子集 Brier 恶化不超过 0.01（绝对值）。
- 报告日期/事件分组的重采样置信区间、类别指标、每股票、官方/媒体/无事件分桶；如区间跨过零，明确统计证据仍有限。
- 对证据通道做删除/时间打乱对照；检查提升不是来源 ID、日期泄漏或数据划分造成。不得只比较旧 SPY 超额收益模型与新绝对收益模型。
- 对有真实证据的样本验证模型响应，不要求所有坏消息一定压低概率；发现反常响应必须检查特征与模型，而不是强行修改输出。

未通过就不把联合模型升级为默认。下一轮改动必须保留该次失败记录；若继续开发导致使用过封存集，应建立新的未触碰时间段。只有真正上线观测、到期成熟的预测才能进入 `prospective` 评估。

## 7. API 与任务契约

所有以下 `/v2` 接口都是待新增。旧接口继续提供旧记录，不改变其返回结构。

| 接口 | 行为 |
|---|---|
| `POST /v2/forecast-jobs` | body `{symbol, kind:"new", source_refs?:[{source_type,source_id}]}`；`Idempotency-Key` 必填；返回 202 + job id |
| `POST /v2/forecast-versions/{id}/revision-jobs` | body `{source_refs:[...]}`；仅手动，至少一条变化来源；检查 symbol、合同、未到期及材料时间；202 |
| `GET /v2/jobs/{id}` | 状态、阶段、覆盖范围、可显示错误、结果版本 id；不返回敏感堆栈 |
| `GET /v2/stocks/{symbol}/workspace` | 当前根/当前版、基线/联合模型状态、待处理信息、行情/信息截止时间、监控状态；无数据为明确 empty |
| `GET /v2/forecast-versions/{id}` | 完整不可变结果及来源引用、概率和不确定性 |
| `GET /v2/forecast-roots/{root_id}/timeline` | 分支版本链、相同 target contract、每版差异及评估状态 |
| `GET /v2/monitor-status` | 上次检查/成功时间、下一次计划、每股票错误、最近触发任务；没有心跳不能显示健康 |
| `GET /v2/evaluations?symbol=...` | 历史研究与前向样本分开返回，统计分母及数据覆盖可见 |
| `POST /v2/evidence-events/{id}/review-versions` | body包含decision(accepted/rejected)、note及可选评分更正；追加用户审阅版本并保留原值，不赋予用户把媒体改成官方来源的能力 |

幂等：相同 key、相同请求返回同一 job；相同 key、不同请求返回 409。同一 root 和相同有效输入 manifest 在并发/重试下最多一个新版本。纯行情未变化而新证据变化必须允许新版本。

`source_refs` 使用现有 `official_filing` / `uploaded_media` 类型与数据库来源 ID；实际加入的是冻结后的来源版本。新预测默认包含筛选后的官方材料和该股票有效手动材料，用户显式选择的材料补充而不是偷偷替换全部背景。不支持的材料渠道必须在结果中显示，不能在请求成功后悄悄丢弃。审阅、更正也按当前 observed 时间可见，并进入下一次研究；不回写原预测。

任务状态：`queued -> running -> succeeded | succeeded_no_change | blocked_data | failed`。`current_stage` 是步骤；`attempts` 保留重试历史。材料缺失、尚无兼容模型分别返回具体 reason，不伪造结果。模型未达发布门槛时任务可以保存完整研究结果，但结果必须 `research_only`、联合概率空，不能因 HTTP 成功而勾选数值融合完成。

使用 PostgreSQL 持久化队列 + 一个本机 worker。API 不在请求线程内长时间调用外部模型；也不只依赖进程内 BackgroundTasks。worker 使用短事务领取和租约、在外部 I/O 前释放事务，完成时验证 lease epoch 后提交；过期执行者不能重复发布结果。心跳 30 秒、租约 5 分钟为初始默认，可配置。

可重试网络/限流失败最多 3 次，退避 1/5/15 分钟；无效引文、来源不合法等内容错误不盲目重试。自动修订在开始处理和提交时都重新检查 72 小时窗口，到期保留未完成原因。失败不能推进研究成功水位线。

错误合同：请求不存在的版本/材料为404；幂等冲突、目标已到期或父版不兼容为409；跨股票/未来材料等字段验证为422；数据库/worker无法接收任务为503。已被接受任务的外部失败写入任务状态，通过GET返回；不把它伪装为请求成功生成预测。LLM事实输入失败时可保留材料与研究失败记录，不能由另一段自由文本替代数值输入。

建议新增入口：`python -m app.forecast_worker --once` / `--poll-seconds 2`。CLI 与 API 调用相同服务；worker 本机常驻并有单独 LaunchAgent 安装脚本，不能假装现有每小时 monitor 就是任务消费者。测试用 `--once`，不启动永久后台进程。

## 8. 每小时监控与自动修订

继续用现有 3600 秒本机定时器。Mac 休眠/关机期间不会实现严格每小时；UI 显示真实 last_success。醒来后按保存的水位线补查，不补造过去决策。

每次循环：

1. 取得监控锁并保存运行记录；逐股票扫描，单只失败不阻止其余股票。
2. 依据已保存 accession/hash 和扫描水位线去重。突破近期 40 份的展示上限，必要时沿官方历史 submissions 分页补足扫描覆盖；若因请求上限未扫完，记录 incomplete/cursor 并继续，不宣称无更新。
3. 保存新目录、近期相关正文/附件；更正保存新版本。只有元数据无正文时不能宣称已分析。
4. 选择当前股票最新的 V2 根预测。自动窗口以该根 `created_at + 72h` 为准，不以最近子版时间重新起算；根目标还必须未到期。
5. 官方来源公开时间严格晚于根创建时间、且不晚于实际本轮时间，才能自动触发；媒体上传和旧文档补发现不自动触发。
6. 将同一股票/根在本轮发现的相关新材料合并为一个任务；没有实质事件也保存检查结论，但不强迫改变方向。
7. 自动任务从该根当前成功版本继续，继承已有有效证据。并发手动任务时通过根锁与版本检查重读最新状态，不能覆盖用户新建根或漏掉新证据。
8. 成功写入新结果后更新状态；失败保留已下载材料，可在窗口内恢复。相同来源重复扫描不得重复版本或重复计费。

切换：V2 未具备模型与 worker 时不得直接替换现有任务为一个无人消费的队列。新增 `OFFICIAL_MONITOR_MODE=legacy|v2`，默认保持 legacy；P6 验收通过后一次切换，禁止同时创建 legacy 复制概率版和 V2 版。旧根预测不自动迁成 V2 根，不满足条件时显示“需要生成一份 V2 预测”。

“当前根”定义为最新成功创建的 V2 根，根内“当前版本”取最新成功发布的版本号；手动选旧版产生的分支也按创建顺序显示，并标出父版。自动计算开始时捕获当前版本号，发布时在短事务内重新检查；若计算期间已有新版本成功，原子拒绝过期发布，重新构建包含最新上下文的任务。根锁不能在等待网络/LLM时长期占用。

## 9. 前端工作流

保留目前五区导航。新组件建议放 `frontend/src/components/`；只拆本次实际涉及部分，不把全部旧 UI 推倒。

- 总览：股票当前联合判断/模型状态、是否有新证据、监控最后成功时间、任务运行/失败状态。待核验材料数量只是辅助指标。
- 预测：生成新预测；展示任务进度、目标日/基准价/两类截止时间；先展示综合结论与关键正反证据，再展开技术元数据。
- 证据：按事件分组，区分新材料/有效背景/被替代/被驳回；保留上传、星级、影响程度与原文引文。无预测股票也可上传和扫描。
- 修订：选历史日期和具体版本、选择新材料；明示保持原目标日。并排显示基线/联合判断的前后变化、触发来源、维持或改变的原因。
- 评估：相同根各版预测对同一个真实结果的得分；与“修订时重新计算的纯行情基线”比较，不能只与较早父版比较后把行情更新收益归因于证据。
- 蜡烛图：根基准、目标日、新消息时点、修订时点及预测/实际窗口；无成熟结果显示待评估。
- 展示 `baseline_probabilities` 与 `joint_probabilities` 的名称和状态；joint 为空时绝不复制 baseline 填充。
- 页面返回/切换股票时不得把旧任务结果挂到新股票；请求带 symbol/job id，取消或丢弃过期响应。前端轮询仅跟踪自己的 job。

人工核验是纠错与追踪功能。通过来源、引文和格式校验的自动流程可产生结果；不强制用户逐份点击同意后才计算。被驳回、来源矛盾或覆盖不完整的材料明确显示，并影响模型可用性判断。
