## 实际链路验证

在独立的、名称以 `test_media_sample_` 开头的 PostgreSQL 数据库中执行，完成后已销毁该数据库：

1. 以 `uploaded_media` 创建 NVDA 手动材料，保留来源 URL、测试用 `published_at=2026-02-10T00:00:00Z`、测试用 `observed_at=2026-09-25T00:00:00Z`、4 星用户自评和原始字节 SHA-256。
2. 以相同截止时间冻结 V2 证据上下文，结果状态为 `pending_review`，不会冒充已确认事实。
3. 冻结事件保留 `analysis_locator={kind: extracted_text_char_range, start: 0, end: 278}`；预测输入清单只引用事件 ID、哈希、来源 URL 和覆盖状态，不复制正文。

本次材料的原始字节 SHA-256：`f3a586eadfe8b724aea3c59732809d3f98311aeb6e9b71c4e72150bcfcfa14cc`。

`published_at=2026-02-10T00:00:00Z` 只是为现有数据库合同提供的 **date-only 测试代理**，不是来源证实的公开时刻；`observed_at=2026-09-25T00:00:00Z` 同样是隔离测试注入的时间，不是本次网页请求的精确观测时刻。因此这条样本只能证明历史研究模式的上传与冻结路径可用，不能用于当天盘中 point-in-time 判断，也不能成为自动修订的触发材料。

## 代码补齐与边界

此前上传媒体能冻结文本，但缺少与 SEC 摘录一致的 `analysis_locator` 和 `coverage_incomplete` 字段，无法给后续引文校验提供统一的文字范围。本次只补齐这两个快照字段，并由 `tests/test_evidence_context_v2.py` 覆盖。

验证结果：`./.venv/bin/pytest -q tests/test_evidence_context_v2.py` 通过（13 passed）。

仍未完成：

- 没有自动抓取/入库任何媒体源；人工上传仍是唯一入口。
- 这条材料是待人工核验的媒体背景，不会改变联合概率，也没有进入训练语料。
- 此次验证只覆盖“上传 → 冻结事件 → 文字定位”；尚未对媒体正文运行真实研究工作流或生成媒体事实引文。
- 单一材料不能满足计划中媒体渠道至少 50 个独立事件的封存验证要求；媒体数值通道仍为 `unsupported_evidence_channel`。

## 2026-09-26：一份媒体正文的真实研究试点

本次只使用上面同一篇 The Conversation 文章的一个短文字摘录，股票仍为 `NVDA`。页面公开标示发布日期为 2026-02-10；来源没有给出精确发布时间，因此数据库中的 `published_at=2026-02-10T00:00:00Z` 仍只是 date-only 代理。测试材料是在 2026-09-26T02:30:08.674741Z 由本系统手动上传并观测到，不能倒推为系统在 2 月已经观察到该文章。

### 开发库记录与真实结果

- 测试上传 ID：`569d6057-06d9-4413-8ea7-69fd318f0f95`；状态保持 `unconfirmed`，4 星只是用户的初步评分。
- 冻结事件 ID：`8d238977-565d-4ed3-886e-d8f9257c2e49`；状态保持 `pending_review`。短摘录的 SHA-256 与冻结 `content_text_sha256` 实际匹配。
- 研究运行 ID：`0c02a5a5-589e-41aa-8128-9ee27c42176b`；状态为 `succeeded`，`time_scope.data_mode=observed`，只消费这一份冻结来源。
- 研究产生 2 条正反论点；两条 `evidence_quote` 均由只读核验确认为冻结 `analysis_text` 的精确子串。它们是来源绑定的模型推断，仍需人工核验，不能当作事实确认、因果判断或预测。
- 同一次事件抽取实际调用 1 次、成功返回但给出 0 条“material event”。因此本次证明的是**媒体正文的研究引文**路径，而不是这段很短行业背景一定能形成结构化媒体事件；没有把零事件伪装成已抽取事件。
- 这轮成功运行的可见模型用量为 1,644 tokens（事件抽取 622 tokens，其余为正反研究调用）。未计算货币金额，因为此记录不保存密钥或价格快照。

该记录最初本应写入一次性隔离 PostgreSQL 数据库，但临时脚本先加载了 `app.config.DATABASE_URL` 再只修改环境变量，导致它实际写入开发库。发现后没有删除、修改或重放该记录，以避免覆盖已有数据；这是一次测试材料而非用户的正式证据。页面上它会在 `NVDA` 的“已上传媒体材料”列表和 V2 手动选材列表出现。只读核验确认当前没有任何 `forecast_versions_v2` 引用了此事件；它不会触发自动修订，且因发布日期已超过新根预测默认 90 天背景窗口，不会自动进入新的默认上下文，只有显式选择时才可能被使用。

随后用正确的临时数据库配置重新做了相同的一来源、三调用试验。研究运行本身也返回 `succeeded` 且两条研究引文都匹配冻结正文，但事件抽取仍返回 0 条事件；试点脚本把“至少一条结构化事件”的额外检查标为未通过。该临时数据库已在退出时销毁。此确认试验额外使用 1,627 tokens；两次试验合计可见用量为 3,271 tokens。后续不再对同一摘录重复调用。

### 仍然不成立的结论

- 这不是自动媒体抓取或完整媒体正文许可方案；材料仍只能由用户手动上传。
- 这不是历史前向证据：来源发布日期早于本次上传，而真正保存的观测时刻是 2026-09-26。
- 这不改变任何 V2 数值概率、没有进入训练，也不证明媒体通道可用。
- 一份短摘录、一个成功研究运行和零条结构化事件远低于计划要求的至少 50 个独立媒体事件封存验证子集；媒体数值通道继续保持 `unsupported_evidence_channel`。
